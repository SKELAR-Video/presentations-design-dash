# SKELAR — набір для слайдів із даними

Три речі, і кожна закриває те, чого не закривають дві інші.

| Файл | Що це | Як користуватись |
|---|---|---|
| `reference.html` | пʼять готових слайдів: щільна таблиця, рейтинг зі смугами, дві таблиці поруч, сітка KPI, графік + текст | «таблиці, KPI й рейтинги роби строго як тут, класи копіюй» |
| `rules-delta.md` | правила, яких немає в основному брендбуку | читати разом із основним брендбуком |
| `check.js` | перевірка відрендереного слайда | відкрити готовий HTML у браузері, вставити в консоль, Enter |
| `ref1–5.png` | як воно має виглядати | для звірки очима |

## Порядок

1. Згенерувати слайд, спираючись на `reference.html`
2. Відкрити його в браузері, прогнати `check.js`
3. Червоне — правити. Показувати тільки на зеленому
4. Далі дивиться людина: перевірка ловить механіку, смак — ні

## Чому не досить самих правил

Приблизно половина дефектів, які ми ловили, — не рішення, а **наслідки**, невидимі без відрендереного:

- `1fr` у CSS Grid бере мінімумом найдовше слово, і колонка їде від рядка до рядка
- flex зʼїдає пробіл після `</b>` — виходить «Ню + Тета— основні»
- інтерліньяж 105% підрізає діакритику (`й`, `ї`, `є`) на кеглі 88px
- нерозривний пробіл усередині CSS-декларації тихо вимикає ціле правило
- `tbody`, який опинився всередині `thead`, забирає всі внутрішні відступи

Жодне з цього не описується словами наперед. Тому `check.js` — не додаток до правил, а третина набору.

## Головне про самі правила

Більшість того, що виглядає як константа, насправді **рішення за виміром**. «Заголовок 44px і без логотипа» — це відповідь для одного слайда, а не правило. Правильна форма: взяти найбільший кегль зі шкали, при якому вміст не переповнений і логотипу лишається охоронне поле.

У кожної межі має бути **дві** сторони: не тільки «не переповнюй», а й «не недовикористовуй». Половина втрат була саме через другу.
